VLM 공부 가이드

Qwen3-VL을 우리 리뷰 데이터에 맞추기 전에, 무엇을 어떤 순서로 보고 어떤 문서를 읽으면 되는지 정리했습니다. 코드 출력은 이 프로젝트 환경(transformers 5.17.0, 로컬 Qwen3-VL-8B config)에서 실제로 돌린 결과입니다.

Part 1

공부 순서와 결론

결론: 논문보다 print(model)이 먼저입니다. 모델을 직접 열어 부품 이름을 확인하고, 은닉상태를 꺼내 읽고, 출구를 바꾸고, 가중치를 조금 바꾸고, 마지막에 덜어내는 순서로 갑니다.

이 순서는 우리 실험 순서(작업 2 → 4 → 1 → 3)와 같습니다. 공부하는 단계마다 그 단계 실험이 바로 손에 남게 되고, 각 단계가 다음 단계에 필요한 감각을 줍니다.

Part 2

구조를 눈으로 보기

실습 1~3은 가중치를 내려받지 않고 config만으로 돌아가서 노트북에서도 됩니다. 아래 출력은 Qwen3-VL-8B로 실제로 돌린 결과입니다. 2B나 4B로 바꿔 돌려 보고 숫자가 어떻게 달라지는지 비교하면 그 자체가 공부가 됩니다.

실습 1

config 읽기

GPU 불필요 · 몇 초

모델의 설계도입니다. 층 수, 차원, 헤드 수, 어휘 크기가 다 여기 있고, 파라미터 계산은 전부 이 숫자에서 나옵니다.

from transformers import AutoConfig
cfg = AutoConfig.from_pretrained("Qwen/Qwen3-VL-8B-Instruct")
t, v = cfg.text_config, cfg.vision_config
print("LLM", t.num_hidden_layers, t.hidden_size, t.num_attention_heads, t.num_key_value_heads, t.vocab_size)
print("ViT", v.depth, v.hidden_size, v.deepstack_visual_indexes)
실제 출력 
LLM 36 4096 32 8 151936
ViT 27 1152 [8, 16, 24]
읽는 법: 어텐션 헤드 32개인데 KV 헤드는 8개입니다. 질문(q)은 32개, 키·값(k, v)은 8개를 나눠 쓰는 GQA 방식이라 k_proj 출력이 4,096이 아니라 1,024가 됩니다(8 × 128). 실습 2 출력에서 확인해 보세요.
실습 2

가중치 없이 구조 출력

GPU 불필요 · 메모리 거의 0

meta 장치에서 모델을 만들면 모양만 있고 숫자는 없는 빈 껍데기가 생깁니다. 80억 파라미터 모델도 메모리 없이 열어 볼 수 있습니다.

import torch
from transformers import AutoModelForImageTextToText
with torch.device("meta"):
    model = AutoModelForImageTextToText.from_config(cfg)
print(model)
실제 출력 (일부, 반복되는 층은 한 번만 표시됨) 
Qwen3VLForConditionalGeneration(
  (model): Qwen3VLModel(
    (visual): Qwen3VLVisionModel(
      (patch_embed): Qwen3VLVisionPatchEmbed(
        (proj): Conv3d(3, 1152, kernel_size=(2, 16, 16), stride=(2, 16, 16))
      )
      (blocks): ModuleList(
        (0-26): 27 x Qwen3VLVisionBlock(
          (attn): Qwen3VLVisionAttention(
            (qkv): Linear(in_features=1152, out_features=3456, bias=True)
            (proj): Linear(in_features=1152, out_features=1152, bias=True)
          )
          (mlp): Qwen3VLVisionMLP(
            (linear_fc1): Linear(in_features=1152, out_features=4304, bias=True)
            (linear_fc2): Linear(in_features=4304, out_features=1152, bias=True)
          )
        )
      )
      (merger): Qwen3VLVisionPatchMerger(
        (linear_fc1): Linear(in_features=4608, out_features=4608, bias=True)
        (linear_fc2): Linear(in_features=4608, out_features=4096, bias=True)
      )
      (deepstack_merger_list): ModuleList( (0-2): 3 x Qwen3VLVisionPatchMerger(...) )
    )
    (language_model): Qwen3VLTextModel(
      (embed_tokens): Embedding(151936, 4096)
      (layers): ModuleList(
        (0-35): 36 x Qwen3VLTextDecoderLayer(
          (self_attn): Qwen3VLTextAttention(
            (q_proj): Linear(in_features=4096, out_features=4096, bias=False)
            (k_proj): Linear(in_features=4096, out_features=1024, bias=False)
            (v_proj): Linear(in_features=4096, out_features=1024, bias=False)
            (o_proj): Linear(in_features=4096, out_features=4096, bias=False)

          (mlp): Qwen3VLTextMLP(

            (down_proj): Linear(in_features=12288, out_features=4096, bias=False)

여기서 찾아볼 것 · Conv3d(3, 1152, kernel_size=(2, 16, 16)): 사진을 16×16px 패치로 자르는 부분입니다. 앞의 2는 동영상 프레임 2장을 묶는 축이고, 사진은 같은 장을 두 번 넣습니다. · 병합기 입력이 4608인 이유: 1,152 × 4. 이웃한 패치 2×2개를 이어 붙여 토큰 1개로 만들기 때문입니다. 그래서 시각 토큰 1개가 사진의 32×32px를 맡습니다. · lm_head가 4,096 → 151,936: 다음 토큰을 15만 어휘 중에서 고르는 출구입니다. 작업 2a는 이 중 6칸만 읽고, 헤드 교체는 이 줄을 4,096 → 6으로 바꿉니다.
실습 3

부품별 파라미터 세기

GPU 불필요

어느 부품이 무거운지 알아야 어디를 얼리고 어디를 학습할지 정할 수 있습니다.

from collections import Counter
cnt = Counter()
for name, p in model.named_parameters():
    parts = name.split(".")
    key = ".".join(parts[:3]) if parts[0] == "model" else parts[0]
    cnt[key] += p.numel()
for k, n in cnt.items():
    print(f"{k:40s} {n/1e6:8.1f}M")
부품파라미터비율해부도에서
language_model.layers6,946M79.2%LLM 36층. LoRA 대부분이 여기 붙습니다
language_model.embed_tokens622M7.1%글 토큰 → 벡터
lm_head622M7.1%출구. 헤드 교체 대상
visual.blocks (+ 임베딩)416M4.7%ViT 27층
visual.deepstack_merger_list120M1.4%DeepStack 연결부 3개
visual.merger40M0.5%병합기
합계8,767M100%
읽는 법: 비전 쪽은 전체의 7% 정도인데, 리뷰 한 건 비용은 거의 전부 시각 토큰에서 나옵니다. "파라미터가 많은 곳"과 "계산이 많은 곳"이 다르다는 점이 작업 1의 출발점입니다. 계산량은 파라미터 수 × 토큰 수로 늘어나기 때문입니다.
실습 4

은닉상태 꺼내기

2B면 GPU 1장 · 리뷰 50건에 몇 분

프로브와 어텐션 풀링 헤드의 입력입니다. 방법은 두 가지인데, 처음에는 옵션 하나로 끝나는 첫 번째가 편합니다.

# 방법 1: 모든 층 출력을 한 번에
out = model(**inputs, output_hidden_states=True)
hs = out.hidden_states          # 길이 37 = 임베딩 출력 1 + 36개 층
last_tok = hs[18][0, -1]        # 18층, 마지막 토큰 → 4,096차원 벡터 하나

# 방법 2: 특정 층에 갈고리(hook)를 걸어 그 층만
saved = {}
layer = model.model.language_model.layers[17]   # 0부터 세므로 18번째 층
h = layer.register_forward_hook(lambda m, i, o: saved.__setitem__("h", o[0] if isinstance(o, tuple) else o))
model(**inputs)
h.remove()
여기서 감 잡을 것: hs[k]의 모양을 찍어 보면 [1, 토큰 수, 4096]입니다. 토큰 수 대부분이 시각 토큰이라는 걸 눈으로 확인할 수 있습니다. 저장할 때는 마지막 토큰만 모으면 리뷰당 4,096개 숫자라 가볍습니다. 토큰 전체를 저장하려면(작업 3) 사진당 토큰 상한부터 정해야 합니다.
실습 5

LoRA 붙이고 다시 출력

meta 장치로도 확인 가능

LoRA를 붙이기 전후로 print(model)을 비교하면 무엇이 바뀌는지가 보입니다.

from peft import LoraConfig, get_peft_model
lcfg = LoraConfig(
    r=8, lora_alpha=16, lora_dropout=0.05,
    target_modules=r".*language_model.*\.(q_proj|k_proj|v_proj|o_proj)",  # LLM 어텐션만
)
pm = get_peft_model(model, lcfg)
pm.print_trainable_parameters()
print(pm.base_model.model.model.language_model.layers[0].self_attn.q_proj)
예상 출력 (8B 차원으로 계산) 
trainable params: 7,667,712 || all params: 8,774,791,408 || trainable%: 0.0874

lora.Linear(
  (base_layer): Linear(in_features=4096, out_features=4096, bias=False)   ← 원래 W, 얼어 있음
  (lora_A): ModuleDict( (default): Linear(in_features=4096, out_features=8, bias=False) )
  (lora_B): ModuleDict( (default): Linear(in_features=8, out_features=4096, bias=False) )
)
계산해 보기: q·o는 r × (4,096 + 4,096) = 65,536개, k·v는 r × (4,096 + 1,024) = 40,960개입니다. 한 층에 212,992개이고, 36층이면 7,667,712개입니다. target_modules를 정규식으로 쓴 이유: q_proj라고만 쓰면 이름이 겹치는 다른 모듈에도 붙을 수 있습니다. ViT 쪽 이름은 qkv라 겹치지 않지만, 어디에 붙었는지는 print로 꼭 확인합니다. 분류 헤드를 새로 달았다면 modules_to_save=["score"]처럼 넣어야 그 헤드도 함께 학습되고 저장됩니다. 빠뜨리면 헤드가 랜덤 초기값 그대로 남습니다.
실습 6

리뷰 한 건의 시각 토큰 세기

GPU 불필요 · 프로세서만

비용 감각을 가장 빨리 잡는 실습입니다. 해상도 상한을 바꿔 가며 같은 사진의 토큰 수를 비교합니다.

from transformers import AutoProcessor
proc = AutoProcessor.from_pretrained("Qwen/Qwen3-VL-2B-Instruct")
enc = proc.image_processor(images=[img], return_tensors="pt")
t, h, w = enc["image_grid_thw"][0].tolist()   # 16px 패치 기준 격자
print("시각 토큰:", t * h * w // 4)            # 2×2 병합으로 4분의 1
우리 데이터 기준: Qwen 기본 설정에서 리뷰 한 건의 시각 토큰은 중앙 3,560개, 상위 10%는 15,552개입니다. 사진당 상한을 256토큰으로 두면 중앙 252개로 줄어듭니다. 같은 리뷰에서 글은 48토큰입니다.

도구 문서

문서는 처음부터 끝까지 읽는 게 아니라, 지금 단계에 필요한 페이지만 찾아 읽습니다. 버전은 이 프로젝트 .venv에 설치된 것입니다. 문서 예제 코드가 안 돌면 버전이 다른 경우가 많습니다.

4 LoRAPEFT, bitsandbytes, Accelerate, (SFT 비교 시) TRL

2.11.0 · cu128

건너뛸 것

Transformers

5.17.0

Qwen3-VL을 불러오고, 입력을 만들고, 출력을 받는 라이브러리입니다. 모델 코드(modeling_qwen3_vl.py)를 직접 열어 볼 수 있는 것도 큰 장점입니다.

읽을 것
Qwen3-VL 모델 페이지, AutoProcessor와 채팅 템플릿, 모델 출력 객체(logits, hidden_states), bitsandbytes 양자화 페이지

Qwen3-VL 모델 문서 모델 출력 객체 bitsandbytes 양자화로 불러오기

PEFT

0.21.0

LoRA와 그 친척들(QLoRA, DoRA, IA³, 프롬프트 튜닝)을 같은 인터페이스로 붙이는 라이브러리입니다. 설정 객체만 바꾸면 방법이 바뀝니다.

읽을 것
LoRA 가이드: r, lora_alpha, target_modules, modules_to_save, merge_and_unload
건너뛸 것
프롬프트 기반 방법들, 여러 어댑터 동시 운용

PEFT LoRA 가이드 PEFT 문서 첫 페이지

bitsandbytes

0.50.2
