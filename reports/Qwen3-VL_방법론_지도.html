Qwen3-VL 방법론 지도

"모델을 바꾼다"는 말에는 서로 다른 손잡이가 일곱 개 들어 있습니다. 아래 해부도에 각 손잡이가 Qwen3-VL-8B의 어디를 건드리는지 찍어 두었고, 절마다 우리 데이터(CESAMARD 리뷰 1,254건)로 예를 들어 채택·후보·안 함을 표시했습니다.

해부도와 손잡이 위치

A입력 바꾸기 B고정 몸통 위에 얹기 C출력 구조 D일부 가중치 학습 (LoRA) E목적함수·학습 방식 F몸통 구조 변경·압축 G시스템

점선 상자는 원래 모델에 없고 우리가 붙이는 부분입니다. 진한 세로줄 18층은 프로브가 은닉상태를 꺼내는 후보 층 중 하나입니다. 분홍 세로줄 0~2층은 DeepStack 특징이 더해지는 층입니다.

먼저 큰 그림: 일곱 개는 단계가 아니라 축입니다

A부터 G는 "가벼운 것부터 무거운 것" 순서로 놓았지만, 하나를 고르면 나머지를 못 쓰는 관계가 아닙니다. 실제 실험 한 개는 보통 여러 축을 함께 씁니다. 예를 들어 작업 4는 D(LoRA)로 가중치를 바꾸면서 C(라벨 점수)로 출력을 읽고, E(분류 손실)로 학습하고, F(4비트 양자화)로 8B를 16GB GPU에 올립니다.

A
입력모델은 그대로. 넣는 것만 바꿉니다.
B
얹기몸통은 얼리고 은닉상태만 읽어 작은 분류기를 학습합니다.
C
출력마지막 출구를 바꾸거나, 출구에서 읽는 방식을 바꿉니다.
D
일부 가중치몸통 숫자를 아주 조금 바꿉니다. 구조는 그대로입니다.
E
목적함수어느 파라미터든, 무엇을 잘하라고 학습시킬지 고릅니다.
F
몸통 구조·압축토큰·층·정밀도를 줄여 싸게 만듭니다.
G
시스템모델 바깥에서 언제 무엇을 부를지 정합니다.
A

입력 바꾸기

가중치를 하나도 바꾸지 않습니다. 언제나 출발점이고, 다른 모든 방법이 이겨야 할 기준선을 만듭니다.

건드리는 곳
프로세서(max_pixels, 크롭), 프롬프트 문자열, 채팅 템플릿
학습 파라미터
0
핵심 감각
입력 길이가 곧 비용입니다. 우리 리뷰는 기본 설정에서 시각 토큰이 중앙 3,560개, 글은 48개라 비용의 거의 전부가 사진에서 나옵니다.
방법하는 일우리 데이터 예시채택
제로샷 프롬프트지시문만 주고 답을 받음"6개 결함 그룹 중 하나를 고르시오" + 리뷰 글 + 사진. 원본 Qwen 성능의 출발점입니다.채택
해상도 낮추기사진당 픽셀 상한을 줄여 토큰 수를 줄임사진당 상한 1,024토큰이면 리뷰당 중앙 1,008개, 256토큰이면 252개로 줄어듭니다. 작업 1에서 가장 강한 기준선입니다.채택
크롭사진 일부만 잘라 넣음결함 박스 중앙값이 사진의 2.9%라, 전체를 낮은 해상도로 넣는 것보다 결함 주변만 높은 해상도로 넣는 편이 나을 수 있습니다. 정답 박스 460건으로 상한선을 잴 수 있습니다.후보
퓨샷 예시정답 예시 몇 건을 함께 넣음예시 하나마다 사진이 붙어 시각 토큰이 수천 개씩 늘어납니다. 글만 있는 예시로 제한하면 쓸 만합니다.안 함
RAG비슷한 과거 사례를 찾아 함께 넣음서비스 단계에서 "비슷한 과거 상담 3건"을 보여 주는 기능으로는 좋습니다. 분류 정확도 실험에서는 빼 둡니다.안 함
소프트 프롬프트글자 대신 학습되는 벡터 몇 개를 입력 앞에 붙임A와 D의 중간입니다. 같은 비용이면 LoRA가 대개 더 잘 되어 비교 우선순위가 낮습니다.안 함
B

고정 몸통 위에 얹기 (프로브·헤드)

Qwen은 얼려 두고, 중간 층의 은닉상태를 꺼내 그 위에 작은 분류기만 학습합니다.

건드리는 곳
LLM 중간 층 출력 hidden_states[k]. 원래 모델에 없는 모듈을 바깥에 새로 붙입니다.
학습 파라미터
선형 프로브 약 2.5만 (4,096 × 6) · 어텐션 풀링 헤드 수십만~200만
핵심 감각
Qwen을 다시 돌릴 필요 없이 은닉상태를 한 번 저장해 두면, 분류기 학습은 노트북 CPU에서도 몇 초면 끝납니다.
토큰 수백~수천 개를 벡터 하나로 줄이는 세 가지 방법

  마지막 토큰    [글 … 사진 … "결함 종류:"] → 마지막 토큰 벡터 1개       가장 흔한 방식
  평균           [t1 t2 … tN]               → 평균                     작은 신호가 묻힘
  어텐션 풀링    질문 벡터 q가 t1…tN을 훑어 → 가중합                     중요한 토큰에 무게

  어텐션 풀링 헤드 (작업 3)
    18층 토큰 전체 (각 4,096) → 4,096→256 축소 → 학습용 질문 k개가 어텐션 → 출력층 여러 개
방법하는 일우리 데이터 예시채택
선형 프로브은닉상태 1개 → 로지스틱 회귀12·18·24·30·36층에서 각각 학습해 층별 곡선을 그립니다. "결함 정보가 몇 번째 층에 가장 잘 들어 있나"를 보는 실험이고, 작업 2b입니다.채택
어텐션 풀링 헤드학습되는 질문 벡터가 토큰 전체를 어텐션으로 모음결함이 사진 한 곳에만 보이는 경우가 많아(불충분 건의 56%), 평균보다 유리할 수 있습니다. 어텐션 가중치를 사진 위에 그리면 결함을 봤는지 정답 박스로 확인할 수 있습니다. 작업 3입니다.채택
멀티태스크 출력층몸통 하나에 출력층 여러 개결함 그룹(6) + 사진에 보이는지(visibility, 라벨 1,166건) + 부위를 한 헤드에서 함께 예측합니다. 작업 3 안에 포함됩니다.채택
MLP 헤드선형층 2개 + 활성함수train 981건에는 표현력보다 과적합 위험이 큽니다. 선형 프로브가 막힐 때만 시도합니다.후보
ViT 특징 프로브LLM 대신 비전 인코더 출력에 프로브"사진만으로 얼마나 아나"를 재는 대조군입니다. 글 정보가 섞이기 전 단계라 결과 해석이 깔끔합니다.후보

"어텐션 헤드"라는 말이 두 가지로 쓰입니다

  • 모델 안의 헤드: Qwen3-VL LLM 한 층에 있는 어텐션 32개(KV는 8개). 내부 부품이라 우리가 건드리지 않습니다.
  • 새로 붙이는 출력 헤드: 위 표의 어텐션 풀링 헤드. "어텐션 헤드를 붙인다"고 하면 보통 이쪽입니다.
C

출력 구조 바꾸기

모델 끝의 출구를 바꾸거나, 출구에서 나온 값을 읽는 방식을 바꿉니다.

건드리는 곳
lm_head (4,096 → 151,936 어휘)와 디코딩 단계
학습 파라미터
라벨 점수 0 · 분류 헤드 교체 약 2.5만 (4,096 × 6)
핵심 감각
지금 qwen_label.py는 JSON을 최대 160~220토큰 생성한 뒤 파싱합니다. 확률이 없으니 라우터에 못 쓰고, 생성 비용이 들고, 형식이 깨질 수 있습니다.
지금      … "결함 종류:" → lm_head → 15만 어휘 중 한 토큰씩 생성 → {"group": "stain", …} → 파싱
라벨 점수  … "결함 종류:" → lm_head → 그룹 이름 6개의 토큰 확률만 골라 비교   → [0.61, 0.20, …]
헤드 교체  … 마지막 은닉상태 → 새 Linear(4096→6)                              → [0.61, 0.20, …]
방법하는 일우리 데이터 예시채택
라벨 점수구조는 그대로. 정답 후보 이름이 나올 확률만 읽음그룹 이름 6개 각각의 로그확률을 계산해 가장 높은 것을 답으로 씁니다. 생성 없이 입력 처리 한 번이면 끝나고, 원본 Qwen의 기준선이 됩니다. 작업 2a입니다.채택
분류 헤드 교체15만 어휘 출구를 떼고 6클래스 출구를 닮LoRA와 함께 학습할 때 출력 방식으로 씁니다. 확률이 바로 나와 라우터 확신도로 이어집니다.후보
JSON 생성문장을 생성하고 파싱지금 방식입니다. 근거 문장이 필요한 서비스 화면에는 남기되, 성능 비교에서는 라벨 점수로 바꿉니다.대체 대상
형식 강제 디코딩문법에 맞는 토큰만 허용JSON이 깨지는 문제만 막고 확률 문제는 남습니다. 라벨 점수가 더 간단합니다.안 함
확률 보정온도 하나를 학습해 확신도를 실제 정답률에 맞춤라우터 임계값을 정하기 전에 필요합니다. ECE로 잽니다.채택
D

일부 가중치만 학습 (PEFT)

몸통 숫자를 아주 조금 바꿉니다. LoRA는 이 가족의 한 방법이고, 구조 변경이 아니라 가중치를 싸게 바꾸는 방법입니다.

건드리는 곳
LLM self_attn.q_proj/k_proj/v_proj/o_proj, mlp.gate_proj/up_proj/down_proj · 병합기 merger.linear_fc1/fc2 · ViT blocks[i].attn.qkv
학습 파라미터
LLM 어텐션 r=8이면 약 770만, LLM 전체 r=16이면 약 4,400만 (8B 전체 약 80억의 0.1~0.5%)
핵심 감각
원래 가중치 W는 얼려 두고, 옆에 작은 행렬 두 개를 붙여 그 둘만 학습합니다. 끝나면 W에 더해 합칠 수 있어 추론 구조와 속도는 원본과 같습니다.
q_proj 한 개를 예로 (8B, 4,096 → 4,096)

  x ─┬─► W  (얼림, 4096×4096 = 1,677만)  ──────────┐
     └─► A (4096×8) ─► B (8×4096)  = 6.6만 학습 ───┴─(+)─► 출력

  q·k·v·o × 36층에 붙이면 약 770만. 학습 후 W' = W + B·A 로 합침
방법하는 일우리 데이터 예시채택
LoRA저랭크 행렬 B·A를 더함원본 Qwen3-VL-8B가 우리 6그룹 기준을 못 따라왔기 때문에, 기준 자체를 가르치려면 가중치를 바꿔야 합니다. 작업 4입니다.채택
QLoRA몸통을 4비트로 줄여 올리고 LoRA8B는 bf16 가중치만 약 17GB라 16GB GPU에 안 들어갑니다. 2B·4B는 bf16 LoRA, 8B는 QLoRA로 갑니다.채택
붙이는 위치 비교어디에 LoRA를 붙일지① LLM 어텐션만 ② LLM 전체 ③ + 병합기 ④ + ViT 뒷단. ③④는 "얼룩·찢어짐 같은 작은 시각 특징을 우리 쪽으로 맞추는가"를 묻는 실험입니다.채택
부분 해동마지막 N층만 전부 학습같은 메모리면 LoRA가 더 많은 층을 건드릴 수 있습니다. 비교용으로만 의미가 있습니다.안 함
DoRA · IA³ · 어댑터LoRA 변형, 활성값 스케일, 층 사이 병목 모듈PEFT 라이브러리에서 설정 한 줄로 바꿀 수 있습니다. LoRA 결과가 나온 뒤 시간이 남으면 추가 비교로 둡니다. 어댑터는 합칠 수 없어 추론이 조금 느려집니다.후보
E

목적함수와 학습 방식

B·C·D가 "어디를 학습하나"라면, E는 "무엇을 잘하라고 학습하나"입니다. 같은 LoRA라도 손실이 다르면 다른 모델이 나옵니다.

건드리는 곳
손실 함수와 정답 데이터의 모양. 모델 부품이 아닙니다.
핵심 감각
우리 silver 라벨 981건은 Claude가 매긴 판단입니다. 이걸로 Qwen을 학습시키면 그 자체가 큰 모델에서 작은 모델로 옮기는 증류입니다. 이름을 붙여 두면 보고서에서 위치가 분명해집니다.
방법하는 일우리 데이터 예시채택
분류 손실 (CE)6클래스를 맞히게B의 프로브·헤드, C의 헤드 교체, D의 LoRA 모두 기본은 이 손실입니다.채택
증류큰 모델의 답이나 확률을 작은 모델이 따라 하게Claude silver 라벨로 학습하는 것, 그리고 8B LoRA 결과를 2B에 옮기는 것 둘 다 해당합니다. "2B가 8B를 얼마나 따라잡나"가 비용 결론으로 이어집니다.채택
SFT (문장 따라 쓰기)정답 JSON 문장을 토큰 단위로 따라 쓰게근거 문장까지 생성하게 만들 때 씁니다. 분류 손실과 정확도를 비교해 볼 만하지만 우선순위는 낮습니다.후보
silver와 gold 나눠 쓰기학습은 silver, 평가는 gold사람 확정 171건은 마지막에 한 번만 씁니다. 실험마다 보면 그 171건에 맞춰 고르게 되어 숫자가 부풀려집니다.채택
전체 파인튜닝80억 파라미터 전부 학습16GB GPU로 불가능하고, 981건이면 과적합합니다.안 함
DPO · 강화학습선호 쌍이나 보상으로 학습"어느 답이 더 나은가" 데이터가 없고, 분류 문제에는 맞지 않습니다.안 함
F

몸통 구조 변경과 압축

진짜 "구조를 바꾸는" 쪽입니다. 새로 설계하는 대신, 있는 구조에서 토큰·층·정밀도를 덜어내 싸게 만듭니다. 프로젝트 주제인 추론 최적화가 여기입니다.

건드리는 곳
병합기 뒤(LLM 입력 직전), LLM 3층 이후, 가중치 저장 정밀도
핵심 감각
몸통 한가운데를 바꾸면 뒤의 층들이 받는 입력이 달라져 사전학습 효과가 깨집니다. 그래서 "끼워 넣기"보다 "덜어내기"가 안전합니다. 덜어낸 뒤에도 정확도가 유지되는지가 실험의 전부입니다.
