HOW TO DECIDE, in this order:
1. Main complaint: the complaint in the TITLE comes first; if the title has none, the one the body talks about most. Use only complaints the review states. If the text is vague but a photo shows a concrete defect, use that defect.
2. defect: pick the code from the LABEL TABLE by the SYMPTOM, not a guessed cause. group6 = the group that code is listed under.
   - not_as_described comes first, but ONLY when the item received differs from what was ordered or advertised. Poor quality, cheap material, "not as expected", or "not as shown in the picture" because it looks cheap is NOT not_as_described.
   - Visibly torn, broken or cracked -> damage. Looks fine but works badly -> function. Made wrong from the start -> manufacturing.
   - non_visual / vague only if nothing concrete is named or shown anywhere.
3. part = where the problem actually is (not where it is shown). Expired food -> contents. Size problems -> whole. Throwaway bag/box -> product_package; jar/bottle kept during use -> container. label/manual only if the label or manual itself is wrong or missing. Service/price -> none. No nameable part (overheating, slowness, colour) -> whole. A part not in the list -> other.
4. visibility: "localized" if the defect (or evidence such as an error message, an expired date, a cracked screen) is visible in a specific region of a picture; "diffuse" if visible but over the whole product (colour, fit, generally thin, a counterfeit that looks clearly different); "not_visible" otherwise (function, taste, service, content, missing items, unrelated photo, a counterfeit that looks identical). Size tags, price tags and numbers in a manual are not evidence.
5. boxes: only when visibility is "localized": 1 to 3 tight boxes around the defect itself, on the picture(s) where it shows best, the best one first. Otherwise "boxes": [].
   - picture = the picture number. bbox_2d = [x1, y1, x2, y2] in pixels of THAT picture: x from its left edge (0 to its width), y from its top edge (0 to its height). Check the size listed above; every number must fit inside that picture.
   - Never box the whole picture or most of it (then the visibility is "diffuse"), and never copy the same box onto another picture.
   - label is the word "defect" (the defect itself is visible: a hole, an insect, smudged print) or the word "evidence" (a sign that proves the problem: an error message, an expired date, a cracked screen). It is never a defect code.

Evidence: keep what the customer says apart from what the pictures show. Write every free-text field in Korean (한국어), except review_span.
- customer_claim: one Korean sentence stating what the customer claims, written as a claim ("고객은 ...라고 주장함"). Keep claims about when or how it happened (for example "arrived torn"), but never state them as facts.
- review_span: the exact words from the title or review that state the main complaint, copied without any change (English, at most 20 words).
- visual_findings: for each picture that shows something related, one Korean sentence on what is actually visible (where it is, its shape or colour). Describe the picture, not the review. If no picture shows the problem, give one entry for picture 1 saying so. box_ref = the number of the matching box in "boxes" (1 for the first box), or null.
- claim_support: "supported" only if a picture itself shows evidence for the main claim (the customer's words are not evidence); "partially_supported" if pictures show only part of it; "not_verifiable" if pictures cannot show it (this does NOT mean the claim is false); "contradicted" only if a picture clearly conflicts with the claim.
- limitations: 0 to 2 short Korean notes on what the pictures cannot confirm (when or how it happened, who caused it, whether it works, taste or smell). Do not guess causes.
